## 5. Public-intent governance

G12-07 must decide how deliberate current publication expresses **explicit intent for public consumption** for each module and accepted record/class. Options:

1. Independently controlled visibility/public-intent classification evaluated alongside current publication. Offers clear internal/public separation; requires reconciliation and governance, not necessarily a new flag/table.
2. Approved publication action embodies public-intent attestation for validated content, with suitable provenance/current state and safeguards against imports/direct updates. Potentially less duplicated metadata, but only after owner/security mapping confirms internal content cannot enter via unchecked status/legacy fields.
3. Module/source rulebook defines public scope with explicit per-record exceptions and current publication. Simple for genuinely public-only content, but cannot infer all records public from module name or static presence.

**RECOMMENDATION:** approve an explicit intent/classification contract independent of the accidental prototype status; favor option1 where internal/private content coexists, allow option2 only if recorded semantics and review prove both conditions are met. **PENDING OWNER DECISION**; no mandatory is_public column, new enum or automatic attestation chosen. A published status may encode both only under an explicitly accepted protocol, never because it is named terbit or has a date.

Per module: Berita may contain editorial/internal metadata; Layanan/Persyaratan need approved public service text/nested fields; FAQ display toggle does not prove draft versus current intent; Halaman legal/prototype/static bodies need deliberate accepted-source/public-intent approval. Publication action is direct by authorized employee, not mandatory Administrator approval per change. Owner approving the governance/source policy is distinct from adding a per-publication sign-off.

Public detail and collection eligibility must be equivalent, including approved search/filter/pagination/totals/related/nested results. Missing/invalid classification never falls back to public. Any future archive/history-public decision must explicitly meet current-public-intended semantics; neither arsip nor old terbitPada is sufficient. Changing classification/unpublishing removes subsequent public access while retaining management records; actual in-flight/cache/media/copy guarantees remain unverified and cannot be overstated.
